## 4. 소프트웨어 현황 (v1, 11/6 기준)
- 앱: Expo SDK 54 / React Native, 재료 4개 태그 입력 + 원하는 맛 텍스트 → Vercel 백엔드 → Gemini → `{"재료명": ml}` 응답을 `pump1~4`로 변환 → ESP32에 HTTP POST.
- ESP32: Wi-Fi STA + WebServer `/makeDrink`, `delay()`로 순차 구동, `MS_PER_ML=1000`(미보정).
- 한계: 블루투스 미지원, 재료 저장 안 됨(앱 재시작 시 초기화), IP 하드코딩, 캘리브레이션·진행상황·비상정지·기록 없음, 디자인 미흡, Expo Go 오류 화면 발생 이력.

## 5. 발견한 문제점 / 정정 필요 사항
1. 회로도 V2: 릴레이 모듈 VCC를 5V로 연결 → ESP32(3.3V) 신호로는 릴레이가 확실히 꺼지지 않을 수 있음 → v3에서 JD-VCC 분리 배선으로 수정.
2. 회로도 V2: 플라이백 다이오드 외 전원 안정화 커패시터·퓨즈 없음, ESP32 USB/외부 5V 동시 연결 주의 없음.
3. 기존 코드 `MS_PER_ML = 1000` (1ml/초) 는 실제 펌프 유량(수십 ml/초 수준)과 크게 달라 캘리브레이션 필수.
4. 선행특허 보고서·특허 PPT에는 여전히 '솔레노이드 밸브' 기반 H/W 차별화가 적혀 있음 → 최신 설계(펌프 단독 제어)와 불일치.

## 6. v2에서 바꾸는 것 (요약 — 상세는 SPEC.md)
- 통신: Wi-Fi/HTTP → **BLE (Nordic UART, 줄바꿈 JSON)** — 공유기·IP 불필요.
- 펌웨어: 비차단 상태머신, 진행률 알림, 비상정지(앱/버튼), 펌프별 유량 보정값 플래시 저장, 시리얼로도 테스트 가능.
- 앱: 재료(펌프) 저장·수정·잔량 관리, 기분/맛/도수/날씨(자동)/상황/성향 입력, AI 레시피 카드·비율 조정, 제조 진행·비상정지, 기록·피드백, 캘리브레이션 마법사, 데모 모드.
- AI: 구조화된 JSON 응답(스키마 강제) + 서버/앱 이중 검증 + 오프라인 규칙기반 대체.
- 회로: JD-VCC 분리, 1000µF 커패시터, 퓨즈, 버튼·LED·부저(선택), 실물형 배선도.

### 7.2 교차 검증 (같은 입력을 양쪽에 넣어 결과 비교)
- **펌웨어 ↔ 앱 데모 기기**: 명령 스크립트 387·757·757개 중 386·756·756개가 출력까지 완전히 같음. 남은 1개는 `setcal`에 소수 셋째 자리 값(4.445)을 넣었을 때의 반올림 차이(실제 앱은 소수 둘째 자리까지만 보냄).
- **앱 ↔ AI 서버 (무작위 10,000건 × 3, 3,000건 × 2)**: 계약 항목 모두 100% 일치. "무알콜·성인 확인 전에는 술 장착·대체 제안 0" 안전 항목은 앱·서버 모두 100%. 참고용 차이 4개(탐색 카드 ml 반올림 등)는 계약 밖이며 안전과 무관.

| APK | 실제 다운로드 주소에서 받은 파일의 SHA-256 이 릴리스와 같음, 앱의 릴리스 판별 함수로 3.0.3 이 3.1.0 을 새 버전으로 알아봄(휴대폰은 이미 3.1.0 이라 앱 안 업데이트는 시험하지 않음) |

- 시험 메모: 3.0.3 은 창이 화면 앞에 있을 때만 받은 뒤 바로 설치하고, 아니면 "받아 두었어요 — 지금 설치"로 물어봄(설계대로).
