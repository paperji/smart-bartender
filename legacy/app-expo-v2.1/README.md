# AI 스마트 바텐더 — 모바일 앱 v2.1

> **보관용이에요.** 지금 앱은 `app/`(v3.0 웹·APK·EXE)이고, 이 폴더의 Expo 앱과 그 AI 서버(`backend/`)는 더 이상 운영하지 않아요. 코드 안의 예전 서버 주소는 쓰지 마세요.

> 팀 **홍당무** · 안양대학교 정보전기전자공학과 캡스톤디자인 Ⅱ (2026-2학기)
> 과제: 사용자의 감정 및 취향 분석 기반 AI 맞춤형 음료 및 칵테일 배합 메이커

기분·맛·도수·날씨·상황·성향을 입력하면 AI(Gemini)가 **기기 펌프에 실제로 장착된 재료만으로** 레시피를 만들고,
블루투스(BLE)로 ESP32 칵테일 메이커에 전송해 음료를 배합합니다.
모든 통신·보정 규칙은 [`../../docs/SPEC.md`](../../docs/SPEC.md) (v2.1) 를 따릅니다. SPEC 과 코드가 다르면 SPEC 이 정답입니다.

## 1. 화면별 기능

| 탭/화면 | 기능 |
|---|---|
| **바텐더(홈)** | 기분(복수 선택 + 직접 입력), 맛 0~5단계(단·신·쓴·탄산), 도수(주류 미장착 시 무알콜만), 현재 날씨 자동 불러오기 또는 수동 선택, 상황, 성향, 잔 용량 → **AI 레시피 만들기** / **새 재료 탐색**. 캘리브레이션 전 안내 |
| **레시피** | 재료 비율 막대, 재료별 ml ± 조정·잔 용량 맞추기, 예상 도수·시간, 맛 프로필, 추천 이유, 가니시·팁, 바텐더 제안, 새 재료 카드(0~1개), 즐겨찾기, **다른 추천(거절)**, **기기로 제조 시작** |
| **새 재료 탐색** | 탐색 카드 1~3개(레시피 이름·설명·재료·메시지 + 펌프 N에 장착하기), 지금 재료로 만들 수 있는 레시피 바로가기, 다시 탐색 |
| **제조 진행** | 펌프별 진행 바, 전체 %, 남은 시간, 큰 **비상 정지**, 기기 안전장치 작동 안내, 완료 후 좋아요/별로예요 → 한 잔 더? |
| **재료** | 펌프 1~4(최대 8) 슬롯: 이름·종류·도수·용량·잔량·색상, 프리셋, 잔량 부족 경고 |
| **기록** | 제조 기록(날짜·기분·피드백), 즐겨찾기 → 다시 만들기 |
| **기기** | 검색(여러 기기 중 선택, 신호세기)·연결·해제·**다른 기기로 변경**·기억한 기기 지우기, 기기 정보(펌웨어, 펌프당 최대 구동, 펌프별 유량과 측정 여부), **캘리브레이션 마법사**, 프라이밍, 세척, 배출 모드, 데모 모드 |
| **앱 설정** | AI 모드(서버/직접 Gemini/오프라인), **AI 서버 주소**·연결 테스트, Gemini API 키·모델, 자동 재연결, 성인 인증 초기화, 데이터 초기화 |

- **데모 모드(기본 켜짐)**: 가상 기기 2대(`SmartBartender-DEMO`, `SmartBartender-DEMO2`)가 v2.1 펌웨어와 같은 규칙(펌웨어 `2.1.0-demo`, `calSet`, 120초 한도, 검증 순서, 0.1초 간격 병렬 기동)으로 동작합니다. 가상 펌프의 "실제" 유량은 3.7~5.2ml/s 라서 캘리브레이션 체험이 실제와 비슷합니다. 측정한 유량은 휴대폰(웹은 브라우저)에 저장되어 **앱을 다시 켜거나 새로고침해도 유지**됩니다. 기기 탭의 "가상 기기 유량 초기화"로 처음 상태로 되돌릴 수 있습니다.
- **오프라인 추천**: 서버/AI 가 실패하면 앱 내장 규칙기반 추천기로 자동 대체("오프라인 추천" 배지). 탐색도 SPEC §5.4 후보 목록(탄산수·토닉워터·레몬즙·설탕시럽·그레나딘 시럽·크랜베리주스·우유·진/보드카/화이트 럼·트리플섹)으로 오프라인에서 만듭니다.
- **성인 인증**: 주류(도수 > 0) 레시피를 처음 제조할 때 만 19세 이상 확인 + 음주운전 경고.
  확인 결과는 AI 요청의 `user.adultVerified`(참/거짓)로 함께 보내요(SPEC §3.1). **성인 확인 전(거짓)** 에는 서버·직접 Gemini·오프라인
  **모든 새 재료 탐색 결과에서 "술을 새로 장착하세요" 카드를 빼요**(새 재료의 도수 > 0, 종류가 증류주·리큐르·와인, 또는 아직 없는 재료 이름이 술 —
  오프라인 후보의 진·보드카·화이트 럼·트리플섹 포함). 이미 장착된 술을 쓰는 카드는 그대로 보여요. 설정에서 성인 인증을 초기화하면 다시 거짓으로 보냅니다.
  **레시피의 제안(suggestions)** 도 성인 확인 전에는 무알콜 선택과 같은 기준으로 술을 장착·대체하라는 말을 지워요(SPEC §3.2 — 서버 결과 재검증·직접 Gemini·오프라인·ml 조정 뒤 재검증 모두,
  `normalize.ts` `sanitizeSuggestions`/`isAlcoholSuggestion`). 술이 없어 무알콜로 만든 오프라인 추천은 성인 확인 전이면 "장착된 주류가 없어 무알콜로 만들었어요." 안내만 보여요(SPEC §3.2 예시 문장, 서버 fallback 과 같은 문장).
- **도수를 맞출 무알콜 재료가 없을 때(NO_MIXER)의 새 재료 탐색**: 장착된 재료가 상한보다 독한 술뿐이라 지금 만들 레시피가 없으면, 탐색 카드는
  **무알콜 재료를 새로 더하는 카드만** 보여요(술만 새로 더하는 카드는 버림 — SPEC §3.3 규칙 8, 판정 `explore.ts` `addsSoftIngredient`, 백엔드와 같음).
  남는 카드가 없으면 AI 를 다시 부르지 않고 앱 내장 탐색 후보(같은 기준)로 채워요.
- **성향(알레르기·싫어하는 재료)**: 성향 칸에 "우유 알레르기", "사이다는 빼 주세요", "우유, 사이다는 싫어요" 처럼 적으면 그 재료는 서버·Gemini·오프라인
  어떤 결과에서도 레시피에서 빠지고, 도수를 낮출 때 섞는 재료로도 쓰지 않아요("우유는 좋고 사이다는 싫어요" 의 우유는 빼지 않음 — 판정 방법은 백엔드와 같은
  `src/lib/ai/preference.ts`). 새 재료 탐색 카드도 같아서, 그 재료를 새로 장착하라는 카드는 나오지 않고 카드 안의 그 재료 줄은 빠져요.
  성향 때문에 쓸 재료가 하나도 없으면 바로 그 이유를 알려 줘요.
  기록·즐겨찾기의 **다시 만들기**도 지금 성향으로 같은 판정을 해서 처음부터 빼고 안내하며, 레시피 화면에서 ml 조정·잔 맞춤 중에 재료가 빠지면 안내 배너와 알림으로 알려 줘요.
- **무알콜 선택**: 레시피의 제안에서도 술을 장착·대체하라는 말(예: "보드카를 장착하면…")은 지워요(백엔드와 같은 술 이름 목록 `src/lib/ai/alcohol.ts`).
  술 판정은 재료의 **도수**로 하므로, 재료 화면에서 종류를 증류주·리큐르·와인으로 고르면 도수가 0일 때 기본 도수(40·20·12%)가 채워지고, 술 종류나 술 이름(보드카·진 등)인데 도수 0%로 저장하려 하면 한 번 더 확인합니다.

## 2. 준비물 — Node.js 22 이상 (중요)

Expo SDK 58 은 **Node 22.13 이상**이 필요합니다. 이 PC 의 시스템 Node 는 20.13.1 이라 그대로는 `npx expo ...` 가 동작하지 않습니다.

**방법 A (쉬움)**: <https://nodejs.org> 접속 → 초록색 **"LTS"** 버튼으로 설치 파일(.msi) 다운로드 → 설치 (모두 "Next")
**방법 B (명령어)**: Windows 터미널(PowerShell)에서
```powershell
winget install OpenJS.NodeJS.LTS
```
설치 후 **터미널을 새로 열고** 확인:
```bash
node -v     # v22.x 또는 v24.x 가 나오면 OK
npm -v
```
그다음 이 폴더(`smart-bartender/app`)에서 한 번만:
```bash
npm install
```

> 한글 경로 주의: `C:\Users\...\캡스톤\...` 처럼 한글이 들어간 경로에서도 웹 실행·EAS 클라우드 빌드는 됩니다.
> 하지만 **PC 에서 직접 안드로이드 빌드(Android Studio/Gradle)** 는 한글 경로에서 실패하는 경우가 많으니
> `C:\dev\smart-bartender-app` 같은 **영문 경로로 폴더를 복사**한 뒤 빌드하세요.

## 3. 실행하기

### 3-1. 웹 + 데모 모드 (가장 빠른 확인)
```bash
npx expo start --web        # 또는 npx expo start 후 터미널에서 w
```
브라우저가 열리면 데모 기기에 자동 연결됩니다. 바텐더 탭 → AI 레시피 만들기 → 기기로 제조 시작.
(인터넷이 없거나 서버를 쓰지 않으려면 앱 설정 → AI 추천 방식 → **오프라인**)

### 3-2. Expo Go 로 열면? (블루투스 불가)
블루투스·로컬 알림 일부는 네이티브 기능이라 **Expo Go 앱에서는 실제 기기(BLE) 연결이 안 됩니다.**
Expo Go 로 열면 기기 탭에 "Expo Go 앱에서는 블루투스 기능을 쓸 수 없어요" 안내가 나오고, **데모 모드**로 전체 흐름(추천 → 제조 → 알림 → 한 잔 더 → 탐색)을 체험할 수 있습니다.
실제 기기는 아래 3-3 의 APK(개발 빌드) 또는 3-5 의 **웹 블루투스(안드로이드 Chrome)** 로 연결하세요.

### 3-3. 휴대폰 설치용 APK 만들기 (사용자가 직접 실행)
EAS 클라우드 빌드를 씁니다 (Expo 무료 계정 필요: <https://expo.dev/signup>).
```bash
npx eas-cli login                                   # Expo 계정 로그인
npx eas-cli build -p android --profile preview      # 설치용 APK (약 10~20분, 클라우드 빌드)
```
- 처음 실행 시 "EAS 프로젝트를 만들까요?", "안드로이드 키스토어를 생성할까요?" → 모두 **Yes**.
- 빌드가 끝나면 나오는 링크/QR 을 휴대폰으로 열어 APK 다운로드 → 설치
  (갤럭시: "출처를 알 수 없는 앱 설치" 허용 필요).
- 앱 첫 실행 시 **"근처 기기(블루투스)"**, **"위치(날씨)"** 권한을 허용하고, 첫 제조 때 나오는 **"알림"** 권한도 허용하세요
  (갤럭시: 설정 > 애플리케이션 > AI 스마트 바텐더 > 알림 에서 나중에 바꿀 수 있음).

### 3-4. 개발 빌드 (코드 수정이 바로 반영되는 APK)
```bash
npx eas-cli build -p android --profile development  # 개발 클라이언트 APK 를 휴대폰에 설치
npx expo start                                      # PC 와 휴대폰을 같은 와이파이에 → 앱이 자동 접속
```
> v2.1 에서 `expo-notifications`(알림) 네이티브 모듈이 추가되었으므로, **예전에 만든 APK/개발 빌드는 다시 빌드**해야 알림이 동작합니다.
> (예전 빌드에서도 앱이 멈추지는 않고, 알림 대신 화면 토스트로 안내합니다.)

### 3-5. 로컬 빌드 (대안, 클라우드 없이)
1. 최신 Android Studio 설치 → SDK Manager 에서 Android SDK Platform 37 · Build-Tools 37 · NDK 27.1 설치
   (RN 0.88 기준 compileSdk 37 / AGP 9.2). JDK 는 Android Studio 내장 JBR(17 이상), 환경변수 `ANDROID_HOME`·`JAVA_HOME` 설정
2. **영문 경로로 폴더 복사** (예: `C:\dev\smart-bartender-app`), 그 폴더에서 `npm install`
3. `npx expo prebuild -p android` → `cd android` → `gradlew assembleRelease`
4. 결과: `android/app/build/outputs/apk/release/app-release.apk`

### 3-6. 웹 배포 — 안드로이드 Chrome 에서 실제 기기 제어 (백업 경로)
Chrome/Edge 의 **Web Bluetooth** 로 APK 없이도 기기를 제어할 수 있습니다. 단, **HTTPS 주소**가 필요합니다.
```bash
npx expo export --platform web        # dist/ 폴더 생성 (public/vercel.json 포함)
npx vercel login
npx vercel deploy dist --prod         # https://xxxx.vercel.app 주소 발급
```
- 안드로이드 Chrome 에서 주소 열기 → 기기 탭 → **데모 모드 끄기** → "기기 선택 (브라우저 창)" → `SmartBartender-XXXX` 선택.
- 제한: 아이폰(Safari)은 Web Bluetooth 미지원 · 탭을 닫으면 연결이 끊김 · 새로고침하면 보통 기기를 다시 선택해야 함
  (브라우저가 `getDevices` 를 지원하면 마지막 기기에 조용히 다시 연결을 시도).
- 웹 알림: PC Chrome/Edge 는 브라우저 알림, **안드로이드 Chrome 은 화면 안 토스트**로 알려 줍니다(브라우저 제한).

## 4. 사용 방법

### 4-1. 처음 켰을 때
- 데모 모드가 켜져 있고, 펌프 1~4 에 무알콜 예시(사이다·오렌지주스·레몬즙·콜라)가 등록되어 있습니다.
- 실제 기기를 쓰려면 **기기 탭 → 데모 모드 끄기**, **재료 탭**에서 실제로 넣은 음료로 바꾸세요.

### 4-2. 기기 연결 · 기기 변경
1. 칵테일 메이커 전원을 켭니다 (상태 LED 가 천천히 깜빡이면 대기 중).
2. 기기 탭 → **주변 기기 검색** → 목록에서 이름(`SmartBartender-A1B2`)과 **신호 세기(강함/보통/약함)**를 보고 눌러 연결.
   기기가 여러 대면 신호가 강한 쪽이 가까운 기기입니다.
3. 연결한 기기는 기억해 두었다가 **앱을 다시 켜면 자동 연결**, 연결이 끊기면 자동 재연결합니다.
4. 다른 기기를 쓰려면 **"다른 기기로 변경"** (연결 해제 → 다시 검색). 기억을 지우려면 "기억한 기기 · 지우기".
5. 안 보이면: 전원 확인 · 2m 이내 · 다른 폰에 연결돼 있지 않은지 확인 · "모든 블루투스 기기 보기" 켜기.

### 4-3. 캘리브레이션(정확도 맞추기) — 처음 한 번 + 재료를 바꿀 때마다
기기 펌웨어는 측정 전(`calSet`=0) 펌프를 기본 유량 20ml/초로 계산하는데, 실제 유량은 체크밸브 때문에 약 3~6ml/초라 **레시피보다 적게** 나옵니다.
바텐더/기기 탭에 "캘리브레이션 전" 안내가 보이면:
1. 마법사 → 펌프 선택 → 용기에 액체를 넣고 "튜브 채우기(3초)"
2. 계량컵(또는 저울, 물 1g ≈ 1ml)을 노즐 아래에 → **10초 구동 시작**
3. 실제로 나온 양(ml)을 입력 → 유량 자동 계산 → **기기에 저장** (ESP32 플래시에 저장, 전원을 꺼도 유지)
4. 펌프에 재료가 등록돼 있으면 "재료 잔량에서 뺄까요?"를 물어봐요. 실제 재료로 측정했으면 **잔량에서 빼기**, 물로 측정했으면 **아니요**.

### 4-4. 추천 → 제조 → 한 잔 더
1. 바텐더 탭에서 입력 → **AI 레시피 만들기**
2. 마음에 안 들면 **다른 추천** (거절로 기록되어 같은 조합은 다시 안 나옴). 2번 연속이면 **새 재료 추천 받기** 안내가 떠요.
3. **기기로 제조 시작** → 진행 화면. 이상하면 **비상 정지**(또는 기기의 정지 버튼).
   휴대폰을 내려놓아도 완료·중단 때 **알림 + 진동**이 옵니다.
   - 제조 중 블루투스가 끊겨도 기기는 정해진 양까지만 붓고 멈춰요. 앱은 자동으로 다시 연결하고(최대 10번, 약 2분), 다시 연결되면 실제 상태를 확인해요.
   - 다시 연결하지 못하면(기기 전원을 끔·너무 멀어짐·자동 재연결 꺼짐) "연결이 끊겨 결과를 확인하지 못했어요"로 정리하고 **닫기**·**기기 탭에서 다시 연결** 버튼이 나와요. 다시 연결하는 중에도 **제조 화면 닫기**로 나갈 수 있어요.
   - 다시 연결되면 기기가 알려 주는 **"마지막으로 끝난 작업"**(`status` 의 `last`, SPEC §2.4)으로 끊긴 동안의 **실제 결과**를 확인해요:
     완료했으면 "완성", 기기 정지 버튼으로 멈췄으면 "정지 버튼으로 멈췄어요"로 기록하고, 기기가 알려 준 양만큼 잔량에서 빼요.
     이미 "결과를 확인하지 못했어요"로 정리했던 제조도 나중에 결과가 오면 고쳐 기록해요(잔량은 처음에 뺀 양과의 **차이만** 더 빼요).
     **닫기**·**기기 탭에서 다시 연결**·**제조 화면 닫기**로 화면을 닫았어도 앱이 그 제조를 기억해 두었다가, 다시 연결되면 기기가 아직 만드는 중이면 진행 화면을 다시 열고,
     이미 끝났으면 화면은 열지 않고 기록·잔량만 실제 결과로 고쳐요(새 제조를 시작하면 예전 제조 확인은 그만둬요). 기록의 레시피 이름은 그 제조를 시작할 때의 레시피 그대로예요.
   - 그 결과가 없고(기기가 다시 켜짐) 기기 가동시간이 제조 시작 후 지난 시간보다 짧으면 "기기가 다시 켜져 제조가 멈췄어요(양 모름)"로 기록해요.
     그 밖(예전 펌웨어 등)에는 예상 시간보다 일찍 대기 상태면 "멈췄어요", 시간이 다 지났으면 "완성(결과 확인 필요)"으로 기록하니 잔을 확인해 주세요.
   - 제조 버튼을 누른 직후 연결이 끊겨 기기 응답을 못 받으면 "실패"로 단정하지 않고 진행 화면에서 "기기 응답 확인 중"으로 기다려요.
4. 완료 후 👍/👎 → **한 잔 더 만들까요?** → [예] 같은 취향으로 새 레시피 / [아니요, 다른 걸 원해요] 새 재료 탐색

### 4-5. 새 재료 탐색
1. 바텐더 탭 **새 재료 탐색** (또는 완료 화면의 "아니요, 다른 걸 원해요")
2. 카드에서 주황색 점선 = 아직 없는 재료. **"펌프 N에 장착하기"** 를 누르면 비어 있는 펌프(없으면 기록상 가장 적게 쓰인 펌프)가 선택돼요.
3. 실제 용기를 바꿔 끼우고 **저장하고 추천받기** → 그 재료를 살린 레시피가 바로 나옵니다.
   (재료를 바꿨다면 프라이밍·캘리브레이션 권장)
4. 빈 기기처럼 새 재료가 **2개**인 카드(예: 탄산수 + 레몬즙)는 첫 재료를 저장하면 두 번째 재료 장착 화면이 이어서 열리고, 둘 다 장착한 뒤에 레시피를 추천해요.

### 4-6. 프라이밍 · 세척
- 프라이밍: 기기 탭에서 펌프 버튼을 **길게 누르고 있는 동안** 펌프가 돌아갑니다(최대 20초). 나온 양은 재료 잔량에서 자동으로 빼요
  (도중에 연결이 끊겨 받은 양만 먼저 뺐다가 다시 연결 뒤 실제 양을 알게 되면 **차이만** 더 빼요).
- 세척: 용기에 깨끗한 물 → 기기 탭 → 세척(펌프당 3/5/10초) → 세척 시작. 끝나면 재료 탭에서 잔량을 다시 확인해 주세요(물로 세척하므로 자동 차감 안 함).

## 5. AI 모드와 서버 주소

| 모드 | 동작 | 실패 시 |
|---|---|---|
| 서버(기본) | `POST {AI 서버 주소}` (SPEC §3, 앱은 서버 응답을 **50초**까지 기다림 — 서버의 Gemini 호출은 1회 14초, 재시도 포함 전체 **20초**까지라 거기에 네트워크·콜드스타트 여유를 더해도 50초보다 짧음. 그래서 서버가 AI 대신 규칙기반 추천을 보내도 앱에 도착해요. 10초가 넘으면 로딩 화면에 "조금 오래 걸리고 있어요") — 요청에 `mode`(normal/explore), `history`(최신 기록부터 최대 10개, 좋아요/싫어요/거절), `user.adultVerified`(성인 확인 여부) 포함. 서버가 이미 보정한 레시피는 잔 용량 맞춤 없이 검증만 하고, 서버의 `notice`·`adjustments`·`warning` 은 화면 안내로 표시 | 오프라인 추천 |
| 직접(Gemini) | 앱이 Gemini REST `generateContent` 직접 호출(**25초** 시간 제한) (JSON 모드 + 응답 스키마 `{recipe, explore}`), 기본 모델 **`gemini-3.6-flash`** (설정에서 변경 가능). 실패 이유는 백엔드와 같은 규칙으로 나눠 보여 줘요(사용량 한도·크레딧 없음·키 오류·모델 없음 등 — 무료 등급의 "check your plan and billing details" 429 는 '크레딧 없음'이 아니라 **사용량 한도**) | 서버 → 오프라인 |
| 오프라인 | 앱 내장 규칙기반 추천 + SPEC §5.4 후보 목록 탐색 | — |

- **AI 서버 주소 바꾸기**: 기기 탭 맨 아래 **앱 설정** → "AI 서버 주소" 칸에 새 주소(예: `https://내프로젝트.vercel.app/api`) 입력 → **저장** → **연결 테스트**. "기본값" 버튼으로 원래 주소 복귀.
  연결 테스트는 HTTP 응답만 보지 않고 상태 확인 응답(`service`·`keyConfigured`)까지 확인해요: "서버 정상(버전·모델)" / "AI 키가 없어 기본 추천만 나와요"(서버 환경변수 `GEMINI_API_KEY` 확인) / "칵테일 AI 서버가 아니에요"(주소 끝이 `/api` 인지 확인).
  기본 주소: 예전 운영 주소는 지웠어요(보관용 — 직접 배포한 주소를 넣어야 동작) (백엔드 폴더 `../backend` 를 v2.1 로 다시 배포해야 탐색 모드가 서버에서도 동작. 배포 전에는 앱이 자동으로 오프라인 탐색을 사용).
- 모든 결과(서버·Gemini·오프라인)는 앱에서 **SPEC §3.3 보정 규칙 1~9**(`src/lib/ai/normalize.ts`, 백엔드 `recipe.js` 와 같은 알고리즘 — 규칙 1 의 성향 제외는 `preference.ts`)와 탐색 검증(`src/lib/ai/explore.ts`, 성인 확인 전 술 장착 카드 제거)을 한 번 더 거칩니다.
  탐색 항목의 `installed`·`pump` 는 서버 값을 믿지 않고 앱이 이름으로 다시 계산합니다.
- 바텐더 탭에서 지금 재료로는 만들 수 없는 조건이면(잔량 0, 무알콜인데 술만 장착, 성향으로 모두 제외, 도수를 낮출 무알콜 재료 없음) 서버를 기다리지 않고 바로 이유를 알려 줘요(서버가 422 를 주는 경우와 같은 판정).

## 8. 문제 해결

| 증상 | 해결 |
|---|---|
| `npx expo start` 가 Node 버전 오류 | Node 22 LTS 설치 (2장), 터미널 새로 열기 |
| 기기 탭에 "Expo Go 앱에서는 블루투스를 쓸 수 없어요" | Expo Go 대신 EAS 로 만든 APK 사용 (3-3) 또는 데모 모드 |
| 알림이 안 옴 | 첫 제조 때 알림 권한 허용했는지 확인 (갤럭시: 설정 > 애플리케이션 > AI 스마트 바텐더 > 알림). 예전 APK 면 다시 빌드 (3-4) |
| 검색해도 기기가 안 보임 | 기기 전원·거리 확인, 블루투스 켜기, 앱 권한(근처 기기) 허용, "모든 블루투스 기기 보기" |
| 앱을 켰더니 "마지막 기기에 자동으로 연결하지 못했어요" | 기기 전원을 켜고 기기 탭에서 다시 검색 → 연결 |
| 연결 직후 "기기 정보(info)를 받지 못했어요" | ESP32 에 v2 이상(BLE) 펌웨어가 올라가 있는지 확인 |
| 기기 정보에 "펌프당 최대 구동: 알 수 없음" | v2.0 펌웨어 — 앱이 60초 한도로 계산. v2.1 펌웨어로 업데이트 권장 |
| "기기 안전장치가 작동했어요" | 펌프가 너무 오래 켜짐 → 튜브 막힘·꺾임, 용기 비었는지 확인 후 다시 시도 |
| 양이 레시피보다 적게 나옴 | 캘리브레이션 (4-3), 튜브에 공기 없는지(프라이밍) 확인 |
| 항상 "오프라인 추천" 배지 | 기기 탭 → 앱 설정 → AI 서버 주소 → **연결 테스트**. 서버가 v2.1 이 아니거나 Gemini 키/크레딧 문제 |
| 항상 "서버 기본 추천" 배지 | 연결 테스트가 "AI 키가 없어 기본 추천만" 이면 서버에 `GEMINI_API_KEY` 설정. 키가 있으면 크레딧·사용량 한도 확인 |
| 웹에서 "기기 선택" 이 안 됨 | HTTPS 주소 + 안드로이드/PC Chrome·Edge, 데모 모드 끄기 |
| PC 로컬 빌드 실패 | 영문 경로로 복사 후 빌드 (3-5) |

## 9. 프로토콜 요약 (SPEC §2, v2.1)
- BLE Nordic UART: Service `6E400001-…`, RX(앱→기기) `6E400002-…`, TX(기기→앱, Notify) `6E400003-…`
- 메시지 = UTF-8 JSON 한 줄 + `\n`. 앱은 180바이트씩 나눠 쓰고, 받은 조각은 `\n` 까지 모아서 해석.
- 명령: `hello` `status` `ping` `make` `stop` `run` `clean` `setcal` `getcal`
- 이벤트: `info`(v2.1: `calSet`, `maxPumpMs`) `status`(v2.1: `last` = 부팅 후 마지막으로 끝난 작업 `{id, kind, result:"done"|"stopped", reason, dispensed}`, 없으면 `null`) `ack` `progress` `step` `done` `stopped`(reason `user`/`button`/`error`) `cal`(v2.1: `calSet`) `pong` `error`
- `make` 검증 순서: ① mode 이상 → `BAD_JSON`, steps 없음 → `BAD_AMOUNT`, 9개 이상 → `LIMIT` ② 각 재료: 펌프 번호 → `BAD_PUMP`, ml ≤ 0 → `BAD_AMOUNT`, 300 초과 → `LIMIT` ③ 같은 펌프 합산 후 300ml·총 500ml·펌프당 120초 → `LIMIT`
- 예전 v2.0 펌웨어(`calSet`/`maxPumpMs`/`status.last` 없음)와도 동작합니다 — 이 값들은 "알 수 없음"으로 표시하고 60초 한도로 계산, 재연결 뒤 결과는 경과 시간·가동시간으로 추정.
- nRF Connect 같은 무료 앱으로 `{"cmd":"hello"}` 를 보내 펌웨어만 따로 시험할 수도 있습니다.
